# Fable's response to Astra round 2 (CAS sync, 26 Sep 2026)

Every claim checked against the source; the Claude verifier's round 2 found the same core problems independently (its R2-1 = CAS-09, R2-2 = CAS-05-R2, N7 = CAS-08) plus a lost in-flight write at cold start (R2-3), a hung request blocking the queue (R2-4) and a second unanswered write replacing the first (R2-5). Protocol: no round 3 with Astra; open points go to Marc.

| ID | Verdict | Action (commit 13fa4fd, c25d6aa) |
|---|---|---|
| CAS-05-R2 | AGREE | The root cause was that the stored base and the local copy were written separately. The bookkeeping (base, unanswered writes) now travels inside the local copy, written in the same go, so whatever copy a cold start finds pairs its content with the base it grew from. A write that lands before the local copy saved it rewrites the copy with the sent state. `descendsFrom` is gone. Test: a reward written to the card before any local save of it survives a cold start (fails on the old code). |
| CAS-08-R2 | AGREE | Follows from the same change: each tab writes its own content with its own base, so two tabs behave like two devices. A tab whose read failed has no base and writes its copy without one; the cold start then merges conservatively and never refunds (test). |
| CAS-09-R2 | AGREE | supabase-js resolves a network failure as an error with an empty code (status 0). Only an error with a PostgREST or Postgres code counts as "nothing written"; everything else, a throw, or no answer within 15 s counts as "may have landed". Up to 10 unanswered writes are kept; a mismatch takes the latest one the card holds as the base. If the card's 20-id list is full and none is found, the merge runs without a base (never counts twice). Tests for the real error shape, two unanswered writes in a row, and the timeout. |
| CAS-05-R2b | PARTLY | Agree the day rule could replace card progress. Replaced by a merge without a base: everything that only grows keeps the union or the larger value, today's tasks keep "done on either device"; a real conflict (a setting, the balance) goes to the side that played the later day, else the card. A stale copy is never on a later day, so it never refunds or reverts. The price: on the first start after this update, a local change that never reached the card and conflicts with a card change can lose. Not zero, but it no longer destroys card progress. |
| CAS-04-R2 | AGREE | With a base, the counters (Sterne, xp, tasks, per-task map, crystals) always add both sides' changes and then take a task ticked on both out once, whatever the net balance. A counter the base never had starts from zero (a browser test found that one). |
| CAS-07-R2 | AGREE | Garden plants and decor unite by id, owned decor and gear unite, crystals merge per family like Sterne. |
| R2-3, R2-4, R2-5 (verifier) | AGREE | A write of the previous page that may still land is kept, restated onto the card, and recognised when it lands. Timeout frees the queue. Several unanswered writes kept. Tests fail on the old code, pass now. |
| R2-6 (verifier) | AGREE | A trip tie now goes to the side that changed it, so a new evening start set on the phone is not undone by the tablet. |

Also changed: no reload after a merge. The page keeps writing its changes onto the card; the other device's progress shows at the next load. That removes CAS-02's reload window altogether.

**Still open, for Marc (Astra rated SHOULD, "acceptable only as an explicit product tradeoff"):** rewards that fire on both devices from the same event outside task ticks can be counted twice in a race: a legacy weekly mission finishing at a day change both devices run from the same card, the cat care flags (feed, pet, play), water sips. Worst case extra Sterne; these features are legacy or behind Extras. Also: old app bundles still write unconditionally until they update, so the migration must go first and old bundles stay last-writer-wins for their short remaining life.

**Marc's ruling (26 Sep 2026):** the double-reward limit above is accepted. The client ships once the Claude verifier's round 3 on the reworked code is clean.
